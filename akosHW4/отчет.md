## 2. Вариант и условие

Морской бой двух игроков под управлением судьи. У каждого игрока своё прямоугольное поле с кораблями. Игроки стреляют по очереди. Судья сообщает результат выстрела. Это может быть промах или попадание или уничтожение корабля. Игрок не видит непроверенные клетки противника. Победа наступает при уничтожении флота противника. При достижении лимита ходов объявляется ничья. Номер варианта в условии не указан.

## 3. Сценарий: сущности и процессы

| Сущность | Реализация |
|---|---|
| Судья | TCP-сервер. Расставляет флоты и проверяет выстрелы |
| Игрок 0 | Клиент. Выбирает клетку и запоминает результат |
| Игрок 1 | Такой же клиент |
| Наблюдатель | Клиент для просмотра игры |
| Поле и корабль | Структуры данных судьи |

В ДЗ № 3 использовалась общая память и семафоры. Теперь используется TCP. Сервер и клиенты можно запускать на разных компьютерах. Поля хранятся у судьи. Копия состояния стратегии тоже хранится у судьи.

При подключении клиент отправляет один байт. Это `0` или `1` для игрока и `o` для наблюдателя. Сервер отправляет игроку настройки игры и состояние стратегии.

```
судья:  отправить ход -> получить координаты -> применить выстрел -> отправить ответ
игрок:  получить ход -> выбрать клетку -> отправить координаты -> запомнить ответ
```

Числа передаются в сетевом порядке байтов через `htonl` и `ntohl`. Чтение и запись повторяются до передачи всего сообщения. На сервере используются `socket` и `bind` и `listen` и `accept`. Клиенты используют `socket` и `connect`.

На 4–5 баллов реализована игра двух клиентов через сервер. На 6–7 баллов добавлен наблюдатель. Он видит оба поля и результаты игры. На 8 баллов добавлена поддержка до 32 наблюдателей. Для обработки подключений используется `poll`. Наблюдатели могут отключаться и подключаться во время игры. История сообщений не сохраняется. Если наблюдатель медленно принимает данные — сервер закрывает его соединение.

Для бонуса добавлено переподключение игроков. При отключении игрока судья сохраняет поля и статистику. Также сохраняется состояние стратегии. Игра ждёт подключения обоих игроков. Если координаты получены не полностью — сервер запрашивает ход снова. Полностью полученный выстрел засчитывается даже при ошибке отправки ответа. Сервер хранит копию генератора случайных чисел и обновляет её после выстрела. При повторном подключении игрок получает известные клетки и состояние генератора. Игрок продолжает партию под тем же номером.

## 4. Пользовательский интерфейс и параметры

Интерфейс остался как в ДЗ № 3. Выводится номер хода и активный игрок. После выстрела выводятся координаты и результат. Также выводятся оба поля. Символ `.` означает неизвестную клетку. Символ `o` означает промах. Символ `X` означает поражённую палубу. В конце выводится статистика. Журнал по умолчанию — `battleship.log`.

Настройки задаются через файл (`-c`) или аргументы `--ключ=значение`.

| Параметр | Значение |
|---|---|
| `size` / `width` / `height` | размеры поля (1–16) |
| `fleet` | длины кораблей через запятую (максимум 16) |
| `touch` | 0 — касания запрещены / 1 — разрешены |
| `placement` | random или ordered |
| `a` / `b` | random / hunt / human |
| `again` | 1 — попадание сохраняет ход / 0 — нет |
| `repeat` | 0 — повтор запрещён / 1 — повтор отнимает ход |
| `first` | начальный игрок 0 или 1 |
| `max_moves` | лимит выстрелов / 0 — без ограничения |
| `seed` | начальное значение генератора |
| `delay` | задержка в миллисекундах |
| `games` | только 1 в сетевом режиме |
| `log` | путь журнала или none |

## 5. Сборка, запуск и завершение

Среда: Linux / GCC / CMake. Команды из каталога `bs`:

```sh
cmake -S . -B build
cmake --build build
```

Запуск в отдельных терминалах. Сначала запускается сервер:

```sh
./bin/battleship server 127.0.0.1 8080 -c configs/classic.cfg --seed=5
./bin/battleship observer 127.0.0.1 8080
./bin/battleship observer 127.0.0.1 8080
./bin/battleship player 127.0.0.1 8080 0
./bin/battleship player 127.0.0.1 8080 1
```

Для запуска на разных компьютерах сервер запускается с адресом `0.0.0.0`. Клиенты используют IPv4-адрес сервера и тот же порт. Порт должен быть доступен в сети.

Для проверки наблюдателя нужно нажать Ctrl+C и снова запустить его. Второй наблюдатель продолжит получать сообщения.

Для проверки игрока нужно нажать Ctrl+C в его терминале. После сообщения об отключении на сервере нужно снова запустить игрока с тем же номером. До этого момента игра стоит на месте. Наблюдатели остаются подключены.

В режиме `human` координаты вводятся как раньше. Например B5. Команда `q` отключает игрока. В конце боя сервер закрывает соединения. Клиенты получают EOF.

```sh
python3 tests/check.py
```

Подключены два наблюдателя. Один был отключён во время боя. Потом он был запущен снова. Оба получили итоговый результат. Результат скрипта:

```
OK: два наблюдателя, отключение и повторное подключение, результат совпал
```

При seed=5 результат совпал с ДЗ № 3:

```

Игрок 0: выстрелов 60, попаданий 20, уничтожено 10
Игрок 1: выстрелов 50, попаданий 10, уничтожено 2
```

При запуске сервера с `-c configs/rectangle.cfg`:

```

Игрок 0: выстрелов 2, попаданий 1, уничтожено 0
Игрок 1: выстрелов 2, попаданий 1, уничтожено 0
```

Сервер и оба игрока завершились с кодом 0. Журналы проверок находятся в `bs/tests`. На нескольких физических компьютерах запуск не проверялся.

Дополнительный тест (после `tests/check.py`):

```sh

```

Игрок 0 был остановлен после 10-го хода. До его повторного запуска новых ходов не было. После 25-го хода так же был перезапущен игрок 1. Все 110 выстрелов и итоговая статистика совпали с обычной партией. Результат:

```
OK: оба игрока переподключены, все 110 ходов совпали
```

Журналы находятся в `bs/tests/reconnect_*.log`.
